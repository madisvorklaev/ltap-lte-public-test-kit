# LtAP Lab v3 Production-Source Mode 2026-08-07

The v3 handoff changes the lab subnet from `192.168.103.0/24` to
`192.168.101.0/24` and assumes the router is running the production ELMO
configuration with only two source-IP lab mangle rules added.

Expected Linux setup:

- LtAP interface: `eno1`
- NetworkManager profile: `LtAP-Lab`
- Management address: `192.168.101.200/24`
- LTE1 source address: `192.168.101.201/24`
- LTE2 source address: `192.168.101.202/24`
- LtAP gateway: `192.168.101.254`
- Table `ltap-lte1`: default via `192.168.101.254`, source `192.168.101.201`
- Table `ltap-lte2`: default via `192.168.101.254`, source `192.168.101.202`

Expected RouterOS checks, once the Ethernet link is up:

- production UDP `5001-5020` rule still marks to `to-lte1`;
- production UDP `5021-5040` rule still marks to `to-lte2`;
- lab source `192.168.101.201/32` rule marks to `to-lte1`;
- lab source `192.168.101.202/32` rule marks to `to-lte2`;
- lab source rules are before production UDP port rules;
- lab source rules use `dst-address-type=!local` and `passthrough=no`;
- `to-lte1` and `to-lte2` each have LTE default plus strict blackhole;
- per-interface masquerade exists;
- no extra RouterOS lab routes/NAT/mangle rules are added from the PC setup.

Verified status:

- No duplicate ARP replies were seen for `.200`, `.201`, or `.202`.
- `LtAP-Lab` was reactivated with the `101.x` addresses.
- Route checks:

  - `.201` uses `192.168.101.254 dev eno1 table ltap-lte1`.
  - `.202` uses `192.168.101.254 dev eno1 table ltap-lte2`.
- RouterOS mangle order is correct:
  1. `ELMO TEST: source via lte1`
  2. `ELMO TEST: source via lte2`
  3. `ELMO: video via lte1`
  4. `ELMO: video via lte2`
- Production UDP ranges are intact: `5001-5020` to `to-lte1`, `5021-5040` to
  `to-lte2`.
- `to-lte1` and `to-lte2` each have an LTE default route and a distance-254
  blackhole.
